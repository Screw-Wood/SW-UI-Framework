# src/framework

This is SW's library source: the public C API and its implementation, organised by module as proposed in [docs/foundational/SYSTEM_DESIGN.md](../../docs/foundational/SYSTEM_DESIGN.md#6-internal-modules).

## Current layout

```text
src/framework/
  sw.h            the single public entry point (see its own header comment)
  core/           sw-init, sw-version (+ sw-version.h.in, generated by meson), sw-error
  application/    sw-lifecycle, sw-application, sw-window
  widgets/        sw-widget (base), sw-label, sw-button, sw-entry
  layout/         sw-box
  style/          sw-metrics
  platform/       sw-gtk4-bridge (internal, not installed)
  accessibility/  sw-accessible
```

This is the head plus the day-zero widget set from [proposal 0003](../../docs/proposal/0003-day-zero-widget-set.md), not the full v1 catalogue in [IDEA.md section 9](../../docs/foundational/IDEA.md#9-what-a-useful-first-release-might-contain). Modules SYSTEM_DESIGN.md section 6 names but that have no code yet (`animation/`, `resources/`, plus the rest of `widgets/` and `layout/` from the broader MVP list) aren't present — see that section's "add a module when it has a real responsibility" guidance. Module names otherwise match that section; this isn't a commitment to keep them exactly as-is.

## Conventions

Source in this directory follows the C API conventions in [SYSTEM_DESIGN.md section 7](../../docs/foundational/SYSTEM_DESIGN.md#7-widget-and-object-model): an `Sw` type prefix and `sw_` function prefix, opaque public structures, documented ownership semantics, and a clear separation between private, experimental, and stable API surfaces. Every public header enforces `#include <sw.h>` as the only direct include point (the `SW_INSIDE_SW_H`/`SW_COMPILATION` guard at the top of each header). Cross-module includes are always written with their module prefix (e.g. `"widgets/sw-widget.h"` from `layout/sw-box.h`), matching how `sw.h` itself includes things, so the installed headers resolve the same way they do in-tree.

## Building

From the repository root:

```sh
meson setup build
meson compile -C build
meson test -C build
```

This builds `libsw-1.0`, runs the unit test in `src/tests/`, and (via `meson install -C build`) installs headers under `$includedir/sw-1.0` plus a `sw-1.0.pc` pkg-config file. See `src/meson.build` for what's actually wired up.

## Status

The head and day-zero widget set from [proposal 0003](../../docs/proposal/0003-day-zero-widget-set.md) have real source and a working Meson build (project at [SYSTEM_DESIGN.md Phase 1](../../docs/foundational/SYSTEM_DESIGN.md#16-development-phases)). This is not yet a release-gated v1 component per [Architecture.md section 4](../../docs/foundational/Architecture.md#4-testing-gate-for-release): only the `core/` module has unit test coverage so far (`src/tests/`); widget, accessibility, and visual-regression coverage for `SwWidget`/`SwBox`/`SwLabel`/`SwButton`/`SwEntry`, and the showcase application, are still outstanding — see [docs/Implementation](../../docs/Implementation/README.md) for current status.
