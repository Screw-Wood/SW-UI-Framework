# Farfuture

This directory is the **far future** in the [docs lifecycle](../README.md#the-lifecycle): ideas that might be done someday, but are not committed work and have no schedule. It is the holding area before [docs/proposal](../proposal/README.md).

## What belongs here

- Ideas that are interesting but not yet something the project intends to build.
- Directions that depend on things that do not exist yet (a stable v1, a second platform backend, more maintainers).
- Items the existing documents already mention as possible later work, such as language bindings or additional platform backends ([SYSTEM_DESIGN.md Phase 5](../foundational/SYSTEM_DESIGN.md#16-development-phases)).

## What does not belong here

- Anything the project has decided to do. That is a [proposal](../proposal/README.md).
- Work in progress. That is tracked in [Implementation](../Implementation/README.md).
- Defects. Those go in [bugs](../bugs/README.md).

## How an idea is written down

One file per idea, named for the idea (for example `language-bindings.md`). It does not need a formal template. Say what the idea is, why it might matter, and what would have to be true before it became a proposal. Keep it short; an idea that needs a detailed design is ready to be a proposal.

## Promoting an idea

When the project commits to an idea, open a proposal for it in [docs/proposal](../proposal/README.md), link the proposal from the idea's file, and remove the idea from this index. Ideas that are decided against can be kept with a note saying so, so the reasoning is not lost.
